# Вёрстка сайта кодом в Tilda

С 28.10.2026 по указанию пользователя сайт верстается HTML/CSS и при необходимости JavaScript в блоках **T123 «HTML-код»**. **Одна содержательная секция сайта — один T123.** Это заменяет прежнее требование собирать дизайн отдельными элементами Zero Block. В Zero Block дизайн не переносить; Vibe Block также не подставлять вместо явно выбранного T123.

## Исходники и состав блока

- Верстать секции по согласованной карте, текстам и актуальным референсам. Первый экран — один T123, каждая следующая секция — следующий T123. Всю страницу в один блок не объединять.
- Хранить готовый код в `tilda-work/blocks/`: например, `01-hero.html`, `02-program.html`. Файл содержит HTML секции, её CSS и необходимый JavaScript; именно этот код используется в Tilda. Локальная проверка этого же исходника не является отдельным дизайном для последующего переноса.
- Для секций задать уникальные ID и ограничить действие CSS их классами или корневыми элементами. Не переопределять стили других страниц и служебных элементов Tilda. Общие токены и шрифты подключать один раз в пределах страницы; правила Cygre — в [реестре шрифтов](<../референсы/Шрифты.md>).
- Адаптив делать в CSS одновременно с каждой секцией, включая промежуточные ширины. JavaScript добавлять только для нужных взаимодействий; не повторять глобальные обработчики и библиотеки в каждом блоке.

## Запись через Tilda MCP

1. Прочитать текущий список блоков через `get_page_records` без полного HTML. Найти существующий T123 нужной секции по сохранённому ID, чтобы не создать дубликат.
2. Для нового блока получить шаблон из `tpls_list` и выбрать **код T123**. В каталоге, проверенном 28.10.2026, ему соответствует `tplid=131`; обозначение T123 не означает `tplid=123`. При выполнении опираться на актуальный каталог.
3. Создать нужный блок через `add_record` с найденным `tplid` и требуемым положением среди соседних блоков.
4. Перед записью вызвать `edit_record` для этого блока и вкладки `content`. Получить точное имя поля HTML-кода и его описание; не угадывать имя поля. Сохранить код через `update_record`, для точечной замены использовать `only_field`. Настройки блока читать и менять отдельно, только при необходимости.
5. Проверить сохранение чтением нужного поля или `get_record_html`. Зафиксировать в `tilda-work/blocks.md` соответствие: секция карты → файл кода → ID страницы → ID блока → шаблон и порядок. Сохранять действующие ID и исходники; при правках обновлять существующий T123.

## Проверка и правки

Проверять секцию в браузере: внешний вид, загрузку шрифтов и изображений, переносы, ширины, ссылки, якоря, клавиатуру и взаимодействия. Если редактор или предпросмотр MCP не исполняет вставленный код, проверить те же исходники локально и явно отметить, что на Tilda ещё не проверено. Чтение сохранённого кода не считать визуальной проверкой. Публикацию выполнять только при уже полученном согласии, после неё проверить результат на Tilda.

При изменениях править код только нужной секции и необходимые общие зависимости. Не пересобирать другие блоки, не переводить HTML в координаты и JSON элементов Zero Block. Отчёты сохранять в `tilda-work/` и `дизайн/`.

Прежние снимки Zero Block сохраняют историю выполненной работы, но не задают способ дальнейшей сборки. Замену существующей реализации выполнять в рамках работы над соответствующей секцией, сохранив исходник и не оставляя на странице два одинаковых экрана. Изменение этих инструкций само по себе не меняет блоки на Tilda и не согласует дизайн.
