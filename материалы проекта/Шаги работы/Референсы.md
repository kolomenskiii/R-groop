# Визуальная основа проекта

Источник визуального направления — новые материалы пользователя в папке `референсы/` и его текущие указания. Существующий `ui-kit.html` и связанные файлы сохранены от прошлого проекта и не используются как основа нового сайта. Название и формат актуальных файлов могут меняться.

Читать эти правила при подборе ниш и работе над визуальными решениями. Не загружать всё содержимое папки на каждом обращении, если текущая задача его не затрагивает.

## Как определить основу дизайна

1. При начале соответствующего этапа сверить [компактный обзор](<../дизайн/референсы-обзор.md>) с актуальными файлами. [Указатель компонентов](<../дизайн/референсы-компоненты.md>) открывать только для поиска нужного компонента. Исходный фрагмент получать по ссылке или указанному диапазону строк, не выводить весь HTML повторно. Если разбор отсутствует или устарел, изучить изменённые материалы и обновить обзор и указатель. Изображения просматривать, ссылки проверять по содержимому.
2. Если есть **актуальный для нового проекта** UI kit, использовать заданные им цвета, типографику, компоненты, сетку, интервалы, состояния и другие правила. Связанные стили, шрифты и изображения учитывать по мере доступности. Существующий `референсы/ui-kit.html` и файлы Cygre относятся к предыдущему проекту и не задают визуальное направление нового сайта. Текущий выбор и предложение по шрифтам указаны в [реестре шрифтов](<../референсы/Шрифты.md>).
3. Если UI kit отсутствует, на шаге 3 разработать дизайн-систему по имеющимся референсам. Выделить из них визуальные принципы: композицию, иерархию, характер типографики, палитру, формы, плотность, графику и стилистику изображений. Не требовать готовый UI kit от пользователя.
4. Если точные параметры не заданы, предложить согласованное решение на основе референсов. Различать наблюдаемые свойства и собственные решения дизайнера; не приписывать картинке неизвестные названия шрифтов или точные значения токенов.
5. Если материалы разного типа, определить роль каждого: например, UI kit задаёт компоненты, скриншот — композиционный приём, изображения — стилистику. Не игнорировать остальные материалы только потому, что найден UI kit. При существенных противоречиях, мешающих выбрать направление, уточнить приоритет у пользователя.
6. В дизайн-системе указать использованные файлы и принципы, которые из них взяты. Сохранять единый визуальный язык на всём сайте и сверять первый экран с согласованной системой.

Референсы задают визуальное направление. Изображённые на них цифры, отзывы, люди, продукты и достижения не становятся фактами о нашем бренде. Для реального содержания использовать подтверждённые материалы выбранной компании и пользователя.

## Если папка изменилась

После сообщения пользователя о замене материалов или при начале нового этапа проверить, какие материалы теперь доступны, включая добавленные и удалённые файлы. Опираться на актуальную папку: не продолжать работу по удалённому UI kit или старым референсам из памяти. Удаление UI kit не требует его восстановления: обновить разбор по новым материалам. Не восстанавливать и не перемещать материалы без поручения пользователя.

Если изменения затрагивают уже утверждённую концепцию, пояснить влияние и согласовать её обновление перед распространением изменений на весь сайт. Результаты аналитики и согласования, которых замена не касается, сохранять.

Если папка отсутствует, пуста или материалы нельзя прочитать, сообщить, чего не хватает, и попросить пользователя предоставить референсы. Не придумывать визуальное направление вместо отсутствующих материалов. Если часть источников доступна, обозначить ограничение и использовать доступные сведения в пределах задачи.

## Другие компьютеры и сессии

Переносить всю папку проекта, включая исходные `референсы/`, `дизайн/референсы-обзор.md` и `дизайн/референсы-компоненты.md`. При неизменных исходниках повторный полный разбор не нужен. Внешние ссылки и недостающие зависимости сохраняют ограничения из обзора; копирование файлов их не устраняет.
